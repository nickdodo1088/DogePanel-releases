# Ubuntu 面板与原生应用兼容性验收

## 范围与基线

以正式面板 `v2.3.3-dp.001`、源码提交 `78bd040` 为基线，验证 amd64 的 Ubuntu
22.04、24.04，并单独记录已结束官方支持的 23.04、23.10。不把容器共享的宿主内核
当作对应发行版的启动、内核升级或 AppArmor 完整验收。

复用官方发布包、校验后的源码下载及依赖缓存；原生应用的安装、编译、配置实验和
重启仅在 `scripts/testbox.sh` 的独立测试环境进行。开发宿主只更新面板程序并做只读
可用性探测，网站、数据库、防火墙及受保护业务配置保持不变。当前工作区的 dgprasp
候选组件不冒充已发布组件。

## 执行顺序

1. 核对普通运维模式实现、标记文件、中文 CLI、Shell 管理及实际权限验收记录。
2. 创建各版本独立用户、网络和挂载命名空间；验证系统身份、官方签名和 HTTPS 下载。
   23 系列只使用官方旧版本归档，不替换系统代号、不关闭签名校验。
3. 安装正式面板，检查默认 HTTPS、非 root Core、私有 Agent、登录及 CLI。
4. 经面板真实安装接口安装 OpenResty、Redis、MySQL、PHP 7.4 / 8.4、dgprasp、ProxySQL。
   记录实际版本、安装方式、依赖、配置、运行用户及任务结果；不能用单独运行二进制
   替代面板安装与管理验收。
5. 建立隔离静态/PHP 网站、测试库与缓存。验证 HTTP/FPM 请求、数据库和 Redis 读写、
   igbinary、配置保存与非法参数拒绝、服务重载/重启、重启后的持久化。
6. 验证 dgprasp 模块加载、正常业务 SQL、参数化查询、明确注入的阻断及事件查询。
   兼容性结果不作为检出率、误报率或性能优于其他引擎的证明。
7. 验证 ProxySQL 后端、账号和规则增改删、热生效、磁盘持久化、监控和读写路由。
   双后端路由夹具不冒充已经配置并验证 MySQL 主从复制。
8. 从真实登录会话检查普通管理与危险操作边界。启用普通运维模式后，确认终端禁止、
   文件越界禁止、Shell 定义只读、CLI 任务可调度与启停；关闭后恢复原授权规则。
9. 复测面板重复升级及测试环境重启，检查应用配置、数据和身份。汇总结果、失败原因
   和受限项；清理本轮完成的临时下载，保留源码、缓存与必要回执。

## 判定与资源控制

每一行均记录通过、失败或未验证，不用“命令返回成功”代替实际服务请求。
发现缺陷先修复受影响项，再重跑相关检查，不反复编译无关发行版或组件。
重型编译限制并行度和内存，日志有界；运行测试使用独立账号、临时凭据和非公共端口。
日志与报告不包含登录密码、连接密码、令牌和真实面板安全入口；文档仅使用
[逻辑相对路径](path-conventions.md)。本轮不自动增加版本号或正式发布。

## 实测发现与修正

- 原生应用内存建议和编译预算曾直接读取宿主机内存。新增 cgroup v1/v2 限额及
  上级剩余空间识别；限定层级遍历，扣除可回收文件缓存，防止无符号计算下溢。
  测试环境在 6 GiB 限额下生成 MySQL 1536 MiB 缓冲池，不再按宿主机容量分配。
  测试预览使用正式基线加本节列出的 Core / Agent 修正，组件与应用目录版本保持不变。
  相关 Go 包测试通过，内存用例通过竞态检查和十轮重复测试。
- nspawn 共享宿主内核的异步 I/O 配额。并行 MySQL 初始化一度因全局额度不足失败，
  未将其归咎于 Ubuntu 或文件权限；测试阶段临时提高额度，收尾恢复原值。
- 修正测试输入的目录/下载文件权限及测试 Agent 切换前置检查；仅重跑被中断或失败
  的项目。编译日志中的警告与任务失败分别记录，不以“存在 warning”直接判定失败。
- 全新系统缺少默认网站目录的上级目录时，创建网站曾提前失败。只读校验现允许
  配置前缀链上尚不存在的目录，仍拒绝已有的可替换目录或符号链接；目录由后续
  文件系统事务创建并设置权限。增加首次建站、校验无副作用及越权路径回归用例。
- 权限分离后，本机审计名称仍曾在 Core 的数据库查询 Agent 表。现统一由本机或
  远程 Agent 返回固定审计元数据，Core 不回退访问 Agent 数据；真实任务日志验证名称
  正确。Agent 审计只读取最多 64 KiB 前缀，保留原请求流、读取错误与关闭行为。
- 隔离检查改为在 Core 的根目录/挂载命名空间内直接降权，避免 PAM 新会话改变
  检查环境；Unix 控制 socket 以连接测试验收，不能用读取 socket 文件代替。
- 测试容器先配置独立网络，再等待 systemd 启动完成；失败或正在启动的容器
  也可完整停止，避免等待顺序造成挂起。四个系统已重新启动并通过静态站点检查。
- 文档路径检查器修正对逻辑目录别名后缀的识别，恢复被误改的示例路径；不改变程序
  安装路径。文档检查独立于业务构建。

### 普通运维模式结论

此功能已包含于 `v2.3.3-dp.001`。服务器管理员运行 `dgpctl` 数字菜单 **32**，或
`dgpctl security enable|status|disable` 管理开关；默认中文，菜单 **34** 或
`dgpctl --language en` 选择英文。菜单 **33** 管理 Shell 任务。

四个系统实测：网页不能关闭管理员标记，MFA 也不能越过上限；终端、越界文件与
Shell 定义修改被拒绝。CLI 审核任务可在网页改时间、启停和执行既定内容；低权限
任务实际以 `nobody` 执行。普通 PHP/网站/软件管理保持可用。完整操作矩阵见
[命令行管理员与面板普通运维模式](cli-operator-mode.md)。

### 边界与回执

- Ubuntu 23 系列的运行通过不代表恢复官方安全维护，新装优先使用仍受支持的 LTS。
- 本表仅覆盖所列 amd64 版本和安装方式；不等于所有 PHP 分支、所有预编译包或 Docker
  安装方式的矩阵。未验证真实 BIOS/UEFI 启动、Ubuntu 自带内核、AppArmor 和内核升级。
- 升级使用正式安装器及同版本本机预览程序，验证已有应用/配置/数据；没有假称完成
  任意旧版本跨版升级矩阵。组件独立加密更新及防护检出率评估不在本表结论内。
- 回执保留在 `PRIVATE_DIR/dogepanel-handoff/codex-ubuntu-compat-20261118/`：
