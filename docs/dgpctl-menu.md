# dgpctl 数字管理菜单

> 文件位置采用逻辑相对路径；执行历史示例前，请按[路径约定](path-conventions.md)替换为当前机器配置。

## 操作方式

以 root SSH 登录安装了 DogePanel 的服务器，执行 `dgpctl` 即可按编号操作，无需记命令。每次执行完成后返回菜单；输入 `0` 或按 Ctrl+D 退出。自动化环境不带参数只显示菜单，不启动服务或等待输入；可显式运行 `dgpctl menu`。

菜单默认中文，不受面板安装语言或系统 locale 影响。数字菜单 34 或 `dgpctl --language en` 切换当前调用语言，不更改面板语言。已有文字命令继续支持。

显式启动、重启面板时会清理对应 systemd 服务的失败计数，避免连续维护触发短期启动限制。服务自身的自动重启仍受 systemd 限流保护。

也支持 `dgpctl 8`、`dgpctl 14`、`dgpctl 27`，以及 `dgpctl logs core`、`dgpctl doctor`。HTTPS 设置失败时不重启；证书完整且有效才允许开启，损坏、部分缺失、符号链接或过期证书保留原文件并报错。已有合法证书复用，不覆盖。

动态密码命令为 `dgpctl mfa status|show|bind|verify|reset|disable`。二维码与手动密钥只在真实终端显示；验证码不作为命令行参数。`reset` 验证新绑定后轮换密钥，`disable` 关闭并清除绑定；兼容旧命令 `dgpctl reset mfa`，表示关闭并清除绑定。变更成功后只重启 Core，退出原面板登录；网站和数据库继续运行。

## 安装后的 HTTPS

**全新安装默认自签 HTTPS，证书或 TLS 启动检查失败就报错，不降级为 HTTP。** 浏览器首次访问会提示不受信任，可继续访问，随后在面板设置更换正式证书。旧 HTTP 安装可用新版 `dgpctl 27` → `1`，或 `dgpctl https enable` 开启；协议切换后用 `dgpctl 14` 查看地址。入口命令识别本机网卡 IP，支持 IPv6 地址格式，不再输出 `$LOCAL_IP` 占位符；NAT 云主机仍需替换为公网 IP。

关闭 HTTPS 仅保留为 SSH 紧急恢复项，必须明确确认。升级旧面板保留已有协议、端口、入口和证书，不自行改变用户访问方式。

升级会替换 `dgpctl` 与语言文件，保留已有安装目录、端口、入口、账号及网页语言；旧安装升级后可直接使用新菜单，无需重装。

## aaPanel 对照与边界

核对了隔离 aaPanel 安装的 `tools.py`、`SYSTEM_DIR/etc/init.d/bt` 和 [aaPanel 官方源码](https://github.com/aaPanel/aaPanel/blob/master/tools.py)，沿用重启、账号、端口、域名/IP 限制、信息查看、日志、MFA、HTTPS、入口的常用编号与操作习惯。菜单按功能分组，避免一次列出无关系统维护项。

DogePanel 的临时登录锁定和会话在内存中，恢复通过重启 core 完成；无需清空业务文件。数据库密码、软件安装、备份策略在各自管理页执行，本次菜单不引入 aaPanel 的 Python 路径、MySQL 强制改密、系统垃圾清理或远程覆盖修复脚本。网站、PHP、数据库、容器和 DogeCDN 服务均不作为菜单服务操作目标。

干净系统真装发现：没有防火墙工具时返回 `ErrNoFirewall`，原先只识别 `ErrNotInstalled`，导致改端口失败。本次仅将这两种缺失状态作为可继续记录端口白名单的情况；冲突、权限或其他运行错误仍然阻止变更，并验证 SSH 等其他规则保持。
