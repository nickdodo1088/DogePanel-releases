# 网站 HTTP、HTTPS 与证书设置改造

## 目标与界面依据

以用户提供的四张截图及兄弟项目 `../Doge/DogeAdminWeb/src/views/servers/detail/` 为界面依据。沿用面板 Vue、Element Plus 和主题变量，复现左侧导航、两列设置表格、端口标签及修改弹窗、折叠高级项与域名证书列表，不引入另一套 UI 框架。

## 实施顺序

1. 域名管理只管理绑定域名，不再显示 SSL 开关；新增 HTTP、HTTPS、HTTPS 证书管理三个独立菜单。已启用功能显示下划线，关闭显示小叉，未读取状态不误报。
2. HTTP 独立启用和端口绑定；支持跳转状态码、目标域名/IP、目标端口以及允许/排除域名，保留请求路径和查询参数，排除证书验证路径。
3. HTTPS 独立启用和端口绑定；按参考表格设置 HTTP/2、HTTP/3、TLS 最低版本、证书、HSTS 和高级选项。证书选择、导入、免费申请均在本站完成，申请成功自动绑定。
4. HTTPS 证书管理按域名列出覆盖、有效期、异常和自动续期，支持搜索、异常筛选、查看、续期和申请，不跳转全局管理。
5. 后端按协议独立保存；保留旧 API 与旧网站。首次读取从当前有效 Nginx 配置恢复，升级本身不修改监听或重载业务。域名新增/删除不改变协议端口。
6. 增加回归测试，隔离环境检验实际 HTTP/HTTPS 请求、端口修改、跳转条件、失败回滚、证书申请绑定及普通非 MFA 管理；实际浏览器检查明暗主题、窄屏和键盘。

## 安全与适配边界

地址只能为本机监听 IP 或通配地址。端口、TLS、加密套件和跳转目标均由后台验证。一个监听地址和端口只允许一种协议。启用 HTTPS 必须有匹配的证书与私钥。HTTP 和 HTTPS 均可关闭，两个协议都关闭时站点配置从 OpenResty 加载目录移出，保留绑定端口、域名与证书以便恢复。保存失败恢复配置、证书文件和数据库。

新建网站时，勾选域名行的 SSL 将按该行端口生成 HTTPS 监听。批量输入支持 `https://example.com:8101`，再次打开批量编辑时保留 SSL 选择。网站创建后可通过 HTTP 或 HTTPS 页面调整各自的端口，通过域名页面管理站点的名称。

参考产品的海外验证集群属于 CDN 分布式功能，单机面板不显示无实际作用的集群设置。HTTP/3 按已安装 Nginx 构建能力显示；0-RTT 默认关闭，开启时拒绝不安全的早期请求，不承诺不支持的 TLS 库提供 QUIC 0-RTT。

依据：[Nginx TLS](https://nginx.org/en/docs/http/ngx_http_ssl_module.html)、[HTTP/3](https://nginx.org/en/docs/http/ngx_http_v3_module.html)、[条件跳转](https://nginx.org/en/docs/http/ngx_http_rewrite_module.html)。

## 验收记录

已完成前后端改造、旧接口适配及数据库迁移。升级只新增协议配置字段，原网站首次读取从实际 Nginx 配置恢复；保存时才采用独立协议模型。

- Go 回归覆盖参数注入、端口冲突、旧配置只读恢复、并发修改指纹、证书覆盖、域名与端口解耦、失败回滚及旧 API；相关用例通过竞态检查。
- Ubuntu 24.04 隔离环境通过 12 项真实 Nginx 检查：HTTP/HTTPS 文件访问、跳转域名/路径/参数、排除域名与 ACME 路径、错误加密套件回滚、被占端口回滚、协议独立开关及证书保留。
- 真实未绑定 MFA 的浏览器会话成功保存 HTTP、HTTPS，并正常打开已安装应用；无失败请求。没有在开发宿主执行这些配置实验。
- 免费证书选择、上传、申请、后台恢复和手动 DNS 续办通过浏览器回归。自动续期仍由现有证书维护任务执行；本轮不为测试域名向公共 CA 发起真实订单。
- 页面沿用参考项目的两列行布局、端口标签、域名加号编辑、证书统计与筛选。明暗主题及窄屏检查见仓库根目录 `design-qa.md`；较长标签采用足够宽的内层列。

单机版本不包含 CDN 验证集群、第三方 CA 的 PKI 文件签发工具或多节点下发。HTTP/3 需要已编译的模块与 TLS 库支持，监听端口需另行确认服务器防火墙、云安全组放行；表单不擅自修改防火墙。0-RTT 默认关闭，GET/HEAD 的业务副作用仍须由应用判断。

## 绑定已有或上传证书

新建网站与网站 HTTPS 使用同一证书库。下拉框先列出覆盖全部站点域名的证书，再按覆盖数量排列其余证书。支持按名称、备注、签发者和类型搜索，面板证书、自签名证书及其他网站的证书均可选。页面会提示域名覆盖范围和有效期状态。

「使用本地签发机构」可以为当前网站域名签发证书并绑定。绑定失败时可以重试同一张已签发的证书。选择面板证书时，当前证书副本与私钥保存在该网站的受保护 TLS 文件中。面板更换证书后可以重新绑定。

选择或粘贴证书后点击「保存证书」即可绑定。上传时校验证书与私钥是否匹配。校验或重载失败时，弹窗保留输入和 OpenResty 返回的错误详情，原证书与配置继续生效。

## 免费证书预检

网站 HTTPS 和全局证书页都提供“检查域名”。面板从 Cloudflare、Google 和 AliDNS 查询公开记录，按域名展示解析地址、验证结果和处理建议。初次申请、手动续办和自动续期也会在后端检查。

- 自动文件验证在 OpenResty 的验证目录临时放置随机探测文件。面板从每个查到的 A、AAAA 地址请求该文件，全部返回正确内容才能提交申请。证书机构下发真实文件后，面板会在通知验证前再核对一次。
- DNS 验证先检查公开 DNS 区域。手动验证指引生成后，面板检查发布的 TXT 值或文件内容。重复检查使用同一份待验证记录，验证信息失效时可重新获取。
- 探测请求限于公网地址及标准 HTTP/HTTPS 验证路径。公共解析结果和服务器出站网络会影响检查，证书机构仍使用自己的网络和签发策略。直连无法访问公网验证地址时，可使用 DNS 验证。 [HTTP-01 和 DNS-01 验证](https://letsencrypt.org/docs/challenge-types/) [签发限额](https://letsencrypt.org/docs/rate-limits/)

## 跨域访问

开启网站或单条反向代理的 CORS 后，面板按配置的协议、主机和端口匹配请求来源。带 Cookie 或其他凭据时填写明确的可信来源，可以每行一个。公开资源可填 `$http_origin` 回显请求的 HTTP 或 HTTPS 来源，面板会关闭凭证支持。使用 `*` 时返回通配符。未启用的站点保持原业务响应。 [Fetch CORS 协议](https://fetch.spec.whatwg.org/#http-cors-protocol)

新配置默认允许 GET、POST 和 OPTIONS。可按业务需要加入 HEAD、PUT、DELETE 或 PATCH。预检缓存为 86400 秒，可设为 0–86400 秒。默认请求头包括 Authorization、Content-Type、If-Modified-Since、Cache-Control、Provider、X-Requested-With、Origin、DNT、Keep-Alive、User-Agent、X-Mx-ReqToken 和 Range。有效预检返回 204，普通 OPTIONS 由业务处理。面板在 OpenResty 的响应过滤阶段统一管理 CORS 响应头，覆盖反向代理和 FastCGI 返回的重复头，并保留 `Vary: Origin`。代理位置的独立配置优先于站点配置。保存时，站点配置只保留可直接阅读的策略参数和调用，共用实现由面板写入其 OpenResty 配置目录。已有策略再次保存时会转换为此格式。

保存后先验证 OpenResty 配置，失败恢复原文件。保存旧版跨域配置时重新校验来源规则。 [OpenResty Lua 响应过滤](https://github.com/openresty/lua-nginx-module#header_filter_by_lua_block)
