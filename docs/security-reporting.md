# 节点安全巡检与只读汇总

## 设计决定

各台服务器安装相同的 DogePanel。管理员明确选择一台面板作为主控，其他面板登记为节点。主控的「安全检测 → 巡检上报」显示登记节点、最后上报时间、漏洞、补丁候选、已恢复项和告警。节点每小时检查一次，也可以在本机页面立即巡检。节点自己判断发现、覆盖范围和可选修复版本，运维人员到对应节点处理并复查。

需要 Wazuh 的节点可在本机运行官方 Manager 和 Indexer。Manager 开启自扫描后，用本机 Syscollector 的软件清单和官方 CTI 匹配漏洞。DogePanel 只读本机索引并签名上报，主控面板继续接收摘要。各节点由本地管理员配置。 [本机 Wazuh 接入](wazuh-local.md) [Wazuh 漏洞关联](https://documentation.wazuh.com/current/user-manual/capabilities/vulnerability-detection/how-it-works.html)

只读汇总服务被控制时，攻击者可能查看、丢弃或篡改汇总页面与该机上的记录。节点持有独有签名私钥，接收端只保存公钥。即使接收端返回任意 HTTP 内容，发送程序也只把 204 状态作为传输回执。节点的任务、配置、文件和升级策略由本机独立掌控。生产环境把接收机放在单独的网络区域，只允许节点访问接收端口，接收机访问节点管理网的流量由网络层拒绝。 [NIST 最小权限与信任边界](https://csrc.nist.gov/pubs/sp/800/207/final) [NIST 日志管理](https://csrc.nist.gov/pubs/sp/800/92/final) [RFC 5848 来源验证与防重放](https://www.rfc-editor.org/rfc/rfc5848) [Schneier 与 Kelsey 的独立审计日志研究](https://www.usenix.org/conference/7th-usenix-security-symposium/cryptographic-support-secure-logs-untrusted-machines)

## 进程与权限

| 部件 | 权限和数据 |
| --- | --- |
| 节点 Agent | 使用已有本机权限读取巡检所需资料。本机管理员配置接收地址、证书和启用状态。Agent 持有节点 Ed25519 私钥，只把定型后签名的数据交给发送进程。 |
| 节点发送进程 | 以 systemd 临时低权限用户运行，读取当次报告及 TLS 目标，禁止监听和接受连接。限制运行时间、内存、文件系统及 Linux capabilities。主动发送到管理员设定的 HTTPS 端点。 |
| 主控接收进程 | 启用主控后由本机 Agent 启动。进程使用动态低权限账号和专用状态目录，入站 HTTPS 用各节点公钥认证。面板通过内部 Unix 套接字只读查询，浏览器沿用主控面板登录。 |

节点只发送结构化资产版本、检查状态、发现及去标识化的告警摘要。事件使用来源、时间、级别和规则，原始日志留在节点。汇总端以 HTML 转义显示数据，通过有大小上限的 JSON 接收固定字段。会话凭据、原始 SQL、请求内容、文件路径和应用配置留在节点。

## 巡检和恢复判定

- 健康检查读取面板服务、已安装应用的运行状态、系统空间和重启提示。内核启动就绪仍由本机系统维护流程验证。
- Debian、Ubuntu 从本机 APT 计划读取同发行版的安全更新候选。检查索引新鲜度。发行版回补按发行版包版本判断，同名软件的上游版本仅作参考。Debian 安装官方 `debsecan` 后，可在节点核对已知 CVE，优先展示高风险及有软件包更新候选的发现。Ubuntu 可通过官方公告单独核对已发布的安全补丁。 [Debian 安全与回补](https://www.debian.org/security/faq) [Debian debsecan](https://manpages.debian.org/bookworm/debsecan/debsecan.1.en.html) [Ubuntu OVAL](https://documentation.ubuntu.com/security/security-updates/oval/)
- 面板管理的 OpenResty、PHP、MySQL 和 Redis 复用本地安装记录和已验证的补丁目录。官方发现与面板可装补丁分别呈现。主机告警使用所选的本机监控来源，汇总台只显示脱敏后的事件摘要。
- 每个来源单独记录成功、部分覆盖、不可用或未启用。某个来源完整完成后，节点可以附上全部发现的标识，即使详情达到数量上限，汇总端也能准确核对旧问题是否已经消失。来源数据缺失或标识达到传输上限时，待处理项继续保留。失联、信息过期和扫描不完整分别呈现。

## 接收与存储

一次 `POST /v1/reports` 用节点 ID、协议域和原始报告字节验证签名。接收端复核报告时间窗、已登记节点、单节点接收频率、请求大小和字段格式。重复发送同一份报告可安全重试，旧报告无法覆盖新报告。接收端只返回状态码。发送进程验证 TLS 主机名，禁用重定向及环境代理。通过页面配对时，节点每次上报都核对主控的证书，解析后跳过节点自身、回环和链路本地地址。通过终端配置时可继续使用本地指定的私有 CA。 [OpenTelemetry 安全实践](https://opentelemetry.io/docs/security/)

接收端 SQLite 事务保存快照、每个节点的待处理和已恢复问题及最近事件。保留期默认七天，按节点限制记录量，定时回收历史，数据库设置磁盘上限。查看端按登记名称、节点状态和问题状态查询。概览展示各节点最新的安全事件，可点节点名称查看详情。汇总服务离线时，节点保留最后一次巡检和发送结果，下次成功上报带来最新状态。

## 实施和验收

1. 实现共享的固定报告格式、签名、TLS 发送和接收存储，增加低权限的独立查看服务。
2. 接入本机定时巡检、终端配置、安全检测页面与手动上报。沿用面板已有的离线选项，主动更新的公共漏洞源与管理员配置的私有汇总目标分别处理。
3. 在隔离环境验证两台节点独立签名、跨节点身份拒绝、重复和过期上报、发现与恢复、不可用来源保留状态、接收端离线、异常响应不影响节点以及默认禁用。验证发件进程的 UID、capabilities 和网络监听约束，再检查实际界面。

本轮在 Debian 12 隔离环境升级现有面板，验证系统安全更新和 Debian CVE 来源、签名上报、拒绝匿名访问、手动修复后的状态更新，以及接收端离线时保留本机结果。Go 回归验证了多节点隔离、截断报告的恢复判定和历史保留。浏览器测试覆盖未配置、启用、手动上报及结果刷新。

角色验收使用两套 Debian 12 DogePanel。启用主控后，节点通过私网主动签名上报，登录主控即可查看收到的 56 条漏洞发现和 14 条补丁候选。验证了主控与节点互斥、主控重启后恢复接收、停用后重新启用保留数据，以及监听地址设置失败后恢复原配置。浏览器覆盖节点搜索、候选版本、已恢复项及告警详情。

## 本地漏洞评估的方案选择

| 方案 | 适合的场景 | 对本项目的取舍 |
| --- | --- | --- |
| Wazuh Manager 本机自扫描与 Indexer | 使用 Wazuh CTI 匹配本机清单，读取漏洞和主机告警 | 管理员配置后使用独立只读账号接入。节点直接取得 Wazuh 的匹配结果，不需要向汇总端上传清单。[本机 Wazuh 接入](wazuh-local.md) |
| 本机 OSSEC 与发行版公告 | 本机文件和认证监控、按发行版判断缺失的安全补丁 | 复用 OSSEC。Ubuntu 22.04 和 24.04 LTS 读取 Canonical 的 USN OVAL，按本机安装状态核对缺失公告。Debian 沿用官方漏洞跟踪数据。[Ubuntu OVAL](https://documentation.ubuntu.com/security/security-updates/oval/) |
| Trivy | 容器镜像、软件包和应用依赖的漏洞扫描 | 适合作为单独的镜像扫描来源。主机巡检先用发行版公告，减少数据库和规则运营成本。[Trivy 漏洞来源](https://trivy.dev/docs/latest/scanner/vulnerability/) |
| Falco | 进程、系统调用和容器运行事件检测 | 适合需要这类审计的选配节点。需验证内核能力与探针权限。[Falco 内核事件](https://falco.org/docs/concepts/event-sources/kernel/) |

Ubuntu 使用发行版提供的 OpenSCAP 作 OVAL 评估，保留官方测试中的包版本、架构和适用范围。Canonical 当前完整 OSV 归档约 61 MB，Ubuntu 24.04 的 USN 文件约 1.7 MB。USN 的范围是已发布补丁的公告。公告中的 CVE 用于说明更新覆盖，安装目标仍由本机 APT 判定。Ubuntu Pro 的独立补丁源、未发布修复的 Ubuntu CVE 和源码安装的软件按各自来源管理。 [Canonical 元数据](https://security-metadata.canonical.com/osv/) [OpenSCAP](https://github.com/OpenSCAP/openscap) [NIST 补丁管理](https://csrc.nist.gov/pubs/sp/800/40/r4/final)

1. 节点低权限任务每六小时检查一次固定的 Canonical HTTPS 地址，将有大小上限的压缩公告原子写入私有缓存。下载仅请求公告文件。遇到缓存缺失、过期或更新失败时，报告显示暂不可用或部分覆盖。
2. 每小时及手动巡检由独立的无外网权限任务运行 OpenSCAP。每条发现显示公告编号、严重度和一个关联 CVE，完整 CVE 清单可点开官方公告查看。原始包清单留在节点，XML 扫描文件在任务结束时清理。本机管理员通过发行版签名源安装 `openscap-scanner` 后启用这一来源。
3. 部署时先更新接收端，再更新 Ubuntu 节点。接收端继续接受旧节点报告。缺少新来源、扫描不完整或规则超出传输预算时保留旧发现。完整有效的复查才能确认公告已不再匹配。
4. 验收覆盖官方公告的真实解析、Ubuntu 隔离扫描、安装状态不匹配、补丁前后判定、超限、缓存失败、出站限制和收集端恢复。采集进程与汇总端的权限模型沿用现有设计。

OpenSCAP 的输入保留全部判定条件和版本规则，公告长描述及引用留给面板解析。本轮 24.04 样本从约 50 MB 缩至约 3 MB 的评估输入，原版 OpenSCAP 对 1,633 项定义给出的判定全部一致。实际扫描使用 40% 单核 CPU、512 MiB 内存上限和 26 秒服务期限。采集任务在独立网络命名空间中仅使用本地 Netlink 获取系统接口信息。

Ubuntu 24.04 隔离验收使用官方 OpenSCAP 与实时报送。节点发现缺失的 USN-8847-1，经 APT 实际更新 OpenSSL 和相关库后重新巡检，汇总页将该公告标为「已恢复」。报告详情达到数量上限时保留完整的发现标识用于恢复判断。Ubuntu 22.04 的官方公告文件也已核对格式和大小。 [USN-8847-1](https://ubuntu.com/security/notices/USN-8847-1)

## 部署和接入

主控与节点使用同一套 DogePanel 安装包。「安全检测 → 巡检上报」可设置本机角色。修改角色、接收地址和登记节点使用已通过动态密码验证的管理员会话。服务器启用了运维限制时，由服务器管理员从终端配置。运维人员可以用普通面板会话查看汇总和节点详情。

1. 在选定服务器的面板点击「设为主控」。选择节点能够访问的本机 IP 和空闲端口，例如 `9443`。域名或映射后的 IP 填入「节点访问地址」。防火墙仅向需要上报的节点放行该端口。启用后复制「主控连接信息」。
2. 在其他服务器的面板点击「设为节点」。填写唯一编号，例如 `web-01`，粘贴从主控面板直接复制的连接信息并保存。节点显示「等待登记」。
3. 复制「节点公钥信息」。回到主控面板点击「登记节点」，粘贴公钥信息并填写可选的显示名称。若编号已关联另一枚公钥，请使用新编号，或由终端管理员确认后更换密钥。
4. 回到节点的「节点设置」，确认已完成登记并点击「启用上报」。可点击「立即巡检并上报」，也可以等定期巡检。主控点击节点名称可查看漏洞、可升级版本和告警，修复后可以筛选已恢复的发现。
5. 要更换主控或停用节点，先在「节点设置」暂停上报。需要更换主控的地址或证书时，在节点重新复制连接信息并保存。要切换主控角色，先在「主控设置」停用接收，此前登记和报告保留。

页面配对在两套独立的 Debian 12 面板完成实测。验证了动态密码授权、配对和登记、首次 HTTPS 上报、主控读取漏洞和补丁候选、监听冲突回退，以及主控停用后重新接收。浏览器回归覆盖角色配置、登记确认、普通查看和受限运维的入口。

### 终端配置

1. 在选定服务器的终端启用主控。地址使用主控现有的私网 IP，端口须空闲。域名访问可在命令末尾另填节点访问的域名。命令会生成 HTTPS 证书，并启动低权限接收进程。

   ```bash
   sudo dgpctl security-report master enable 10.60.0.5:9443
   sudo dgpctl security-report master ca > master-ca.pem
   ```

2. 将上一步的公开证书交给各节点。节点管理员在节点终端配置唯一的编号、主控地址和证书，并保存输出的公钥登记文件。

   ```bash
   sudo dgpctl security-report configure web-01 https://10.60.0.5:9443 master-ca.pem > web-01.json
   ```

3. 将节点公钥文件交给主控管理员，在主控终端登记。密钥轮换使用原节点编号重新登记。节点的签名私钥保存在本机。

   ```bash
   sudo dgpctl security-report master register web-01.json '网站节点 01'
   sudo dgpctl security-report master status
   ```

4. 登录主控 DogePanel，打开「安全检测 → 巡检上报」。总览可筛选有漏洞、可升级和缺少近期报告的节点。点节点名称查看软件版本、候选修复、已恢复发现和告警。在节点的同一页点击「立即巡检并上报」，也可在节点终端运行 `sudo dgpctl security-report run`。
5. 暂停节点上报用 `sudo dgpctl security-report disable`。停用主控接收用 `sudo dgpctl security-report master disable`，接收记录随本机保留。切换角色前，先停用当前角色。使用 `sudo dgpctl security-report master remove web-01` 会撤销该节点公钥，并在主控清理此节点的记录。

主控接收进程由 Agent 管理，Agent 重启后会恢复监听。HTTPS 接收端点接收节点签名报告。节点总览和详情通过本机 Unix 套接字读取，由主控面板权限保护。跨节点的配置及修复由各自管理员处理。已配置的节点继续使用原有签名协议，切换接收地址时用原编号重新登记；历史独立接收服务的存储另行保留。

Debian 的 CVE 检查可选用官方 `debsecan`，APT 索引需保持新鲜。Ubuntu 22.04 / 24.04 LTS 的公告检测使用官方 `openscap-scanner`。启用 Wazuh 的节点采用本机 Wazuh 的漏洞与主机告警结果。 [Wazuh 本机接入](wazuh-local.md)
